# SISO-REF-056-2018 compliance assessment — the `xml/` set

**Date:** 2026-10-14 · **Target:** `xml/` (master + 12 family files) ·
**Baseline:** upstream `opendis7-source-generator` @ `7d27161` (the v0.1.0
source-of-truth commit, per `MANIFEST`; numbers measured 2026-10-14) ·
**Tool:** `scripts/ref056_check.py` (read-only census; re-run after any `xml/`
change and refresh this report if numbers move)

**Source:** SISO-REF-056-2018, *SISO Reference for XML Style Guide*, 1 Aug 2018.

## Scope caveat (read first)

REF-056 governs **XSD schema products** (MSDL, C-BML, BOM lineage) and adoption is
voluntary by its own §1.1. The PDU XML set is a **generator vocabulary** — root
`<classes>`, `xi:include` composition, and the upstream file header says "This is not
an XML Schema!" So most best practices apply **by analogy**, and several are
structurally N/A. This report scores the transferable subset and flags where the
analogy breaks. The upstream `DIS_7_2012.autogenerated.xsd` (a *capture-log* schema
for wire instances, not for the vocabulary) is assessed briefly at the end.

## Notes on the remaining "duplicates" (Principle 16)

The 14 duplicate-signature groups are **distinct spec types that happen to share a wire
shape**, not authoring accidents: `CreateEntityPdu`/`RemoveEntityPdu`/`RequestID`
(single 32-bit field), `AggregateMarking`/`EntityMarking`,
`AngularVelocityVector`/`Vector3Float` (and by the same argument `Vector3Double` ≡ the
WorldCoordinates role), `DataQueryDatumSpecification`/`DatumSpecification`,
`LEMunitionDescriptor`/`MunitionDescriptor`, `EngineFuel`/`StorageFuel`. REF-056's own
carve-out ("the definition of alternative representations should not be considered
duplication", §6.3.5) partially applies. Consumers must keep them distinct (distinct
UIDs/classes); only *code-level* sharing is optional — the `aliasFor` mechanism
(20 abbreviation aliases, inherited upstream) already does this where the spec itself
names an abbreviation.

## The upstream capture-log XSD (`DIS_7_2012.autogenerated.xsd`)

Carries `version="7.0"` (BP 8-31 half-pass) but: **no `targetNamespace`** (BP 8-29/8-30
fail), **anonymous `complexType` definitions** (BP 8-12 fail), and **persistent
information in XML comments** (PDU numbers — BP 8-42 fail). Its global-element + `ref`
structure is the one BP-8-13-conformant thing about it. If this schema is ever
regenerated from the corrected set, it needs the same namespace/version treatment.

## Overall verdict

The `xml/` set is materially **more** REF-056-conformant than the upstream baseline:
enumeration joins moved from prose comments to machine-readable attributes, conditional
selection became explicit vocabulary, 2 duplicate groups were eliminated, 8
non-conforming identifiers were cleaned, and class documentation is at 100%. The
remaining failures are **structural to the xmlpg vocabulary itself** (no namespace, no
version, no governing schema, no samples) — plus one actionable on this repo's own
additions: the correction vocabulary is currently bare attributes. Holding *our*
additions to REF-056's standard is the concrete next step.

## Recommended actions (ranked)

1. **Formalize the correction vocabulary** (`presentIf`/`when`/`countExpression`/
   `countListFieldName`/`bitCountExpression`/`uid`/`size`/`aliasFor`) as a namespaced,
   schema-valid annotation vocabulary with a small XSD, owned here — this is literally
   BP 8-43/8-44, and it upgrades the vocabulary from convention to definition
   (consumers can validate `xml/` structurally, not just via `validate.py`).
2. **Add version/provenance metadata** to `xml/` — either a `version`/`provenance`
   attribute group on `<classes>` or a manifest sidecar (date + upstream commit +
   fix-set id; `MANIFEST` already holds the content for the latter).
3. **Ship sample instance documents** exercising every documented component (BP
   11-1/11-2) — these double as fixtures for downstream generator conformance tests.
4. **Add a documentation-coverage lint** to the conformance suite (`classes == 100%`,
   fields ≥ target), and opportunistically document the remaining ~1076 fields,
   prioritizing fields named in conditional/count expressions.
5. **Decide the fate of the 4 `default="0"` paddings** — either rename to
   `expectedValue` (documentation, not mutation) or document that generators must
   ignore it. REF-056's rationale (validation must not mutate instances) is exactly the
   generator's situation.
